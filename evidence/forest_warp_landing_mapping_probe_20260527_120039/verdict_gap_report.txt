## Root Cause

**wTilesetBlocksPtr (0xD529) is STALE after savestate reload.**

The adjacent tile oracle's `_decompose_tile()` function reads from
`wTilesetBlocksPtr` in WRAM (0xD529), which is set during `LoadTilesetHeader`
and NOT refreshed after savestate. After loading `cp09_viridian_forest_south_entrance.state`,
the pointer points to stale/non-FOREST block table data, returning WRONG tile IDs:

| Direction | Runtime tile_id | Source-correct tile_id | Source-correct passable |
|-----------|----------------|------------------------|------------------------|
| under (player) | 0x0D           | 0x20                   | YES (Forest_Coll includes 0x20) |
| up (in front)   | 0x0A           | 0x22                   | NO                      |
| left           | 0x99           | 0x20                   | YES                     |
| right          | 0x99           | 0x20                   | YES                     |

**Important**: tile 0x20 is in Forest_Coll passable list, so the player CAN move
LEFT and RIGHT from position (17,47). Only UP is genuinely blocked (tile 0x22
is not passable — it's the top decorative half of the warp block).

## Required Fix

In `_decompose_tile()`: replace
  `blocks_ptr = self.emu.read_u16(ADDR_TILESET_BLOCKS_PTR)`
with
  `blocks_ptr = self._get_correct_blocks_ptr_from_tileset_table(tileset_id)`

The tileset table at ROM 0xC7BE (24 entries × 12 bytes each) provides the correct
block table address for each tileset. The function should:
1. Read tileset_id from WRAM (0xD52F) — RELIABLE after savestate
2. Look up table_base + tileset_id * 12 → bytes[1:3] = block_ptr
3. Convert to flat ROM address using entry[0] as bank
